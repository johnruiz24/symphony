✓ PubSub is simple (single channel, predictable)

CHALLENGES FOR REACT INTEGRATION:
✗ Separate build pipeline (npm + mix)
✗ Need to handle real-time updates (WebSocket or SSE)
✗ Asset versioning and cache-busting
✗ Development experience (two dev servers)

2. Deploy to elixir/priv/static/ (bundled with Elixir)
3. Add SSE endpoint for real-time updates (simple, HTTP-based)
4. Keep API endpoints unchanged
5. Phase out LiveView gradually

- Week 2: Implement all dashboard components, styling
- Week 3: Real-time integration, E2E tests
- Week 4: Polish, optimization, documentation

PRACTICAL DETAILS FOR REACT DEV
================================================================================

API Endpoint: GET /api/v1/state
Response includes:
- counts.running (metric card)
- counts.retrying (metric card)
- running[] array (table data)
  - issue_identifier
  - state (status badge)
  - turn_count
  - tokens.total_tokens
  - last_event_at (timestamp)
- retrying[] array (retry table data)
  - attempt, due_at, error
- codex_totals (metric cards)
  - input_tokens, output_tokens, total_tokens, seconds_running
- rate_limits (pre-formatted JSON)

Real-time Updates (Current):
- Phoenix PubSub broadcasts ":observability_updated" event
- LiveView receives and re-fetches state
- For React: either poll or implement SSE endpoint

State Machine:
- Orchestrator (GenServer) maintains issue state
- Issues cycle: Polling → Claimed → Running → Completed → Retry/Terminal
- Max concurrent agents: configurable
- Poll interval: configurable (default 5s)

Current Dashboard UI:
- Hero card (title + live status)
- 4 metric cards (running, retrying, tokens, runtime)
- Rate limits section
- Running sessions table (live updates)
- Retry queue table

Current Design System:
- Accent color: #10a37f (teal)
- Background: #f7f7f8 (light gray)
- Text: #202123 (dark gray)
- Danger: #b42318 (red)
- Shadows + borders defined as CSS variables
- Single-column responsive layout
